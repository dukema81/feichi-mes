# 飞驰MES系统 项目说明与操作手册

> 版本 ｜ V1.0 · 2026 年 10 月 · 飞驰精密制造（苏州）有限公司 制造信息化项目组

## 1 项目说明

### 1.1 这是什么

飞驰MES系统是飞驰精密制造的**制造执行层**：承接飞鹰 CRM 的销售订单与飞泉 SCM 的到料结果，把"要做多少台"变成"每张工单在每条产线每道工序做到哪一步"，并把过程中的质量、设备、人员、批次数据全部沉淀下来，形成可追溯、可分析、可对接的数据底座。

### 1.2 能解决什么问题

| 现场痛点 | 系统解法 |
| --- | --- |
| 计划在 Excel，进度靠问 | 排产甘特 + 工单状态机，每张单"卡在哪道工序"一屏可见 |
| 产量算不准（重复计数） | 末工序口径统一产量，报表与入库量偏差 < 2% |
| 缺料工单下到现场才停工 | 齐套率 100% 才能下达，缺口清单一键可催 |
| 首件不做就批量生产 | 首件必检规则，未合格直接拒绝报工 |
| 未检成品混入库存 | 完工检合格才允许入库 |
| 批次出问题只能全召回 | 批次父子链，正向展开到原料、反向定位流向 |
| 设备停机原因不明、OEE 算不出 | 状态变更强制填原因，自动汇总 OEE / MTBF / MTTR |
| 保养靠人盯 | 保养计划逾期/临期提醒，点检异常自动置故障 |

### 1.4 技术栈一览

- 后端：Python 3.8+ 标准库（`http.server` + `sqlite3`），**零第三方依赖**。
- 数据库：SQLite（WAL 模式），单文件 `backend/data/feichi.db`。
- 前端：原生 HTML / CSS / JavaScript，无框架、无构建、无 CDN。
- 集成：REST（API Key）+ Webhook（HMAC-SHA256）+ 增量同步（游标）。

## 2 快速开始

### 2.1 启动服务

```bash
cd feichi-mes
python backend/server.py
```

启动后访问 `http://127.0.0.1:8021`，自动跳转登录页。

**首次启动**会自动建库并写入确定性演示数据（4 车间 / 7 产线 / 25 工位 / 25 设备 / 26 物料 / 37 工单 / 55 批次等），约 1~2 秒完成。

## 3 页面操作指南

### 3.1 制造驾驶舱（dashboard）

**看什么**：6 项 KPI（在制工单、本月产出、综合 OEE、良品率、设备异常、保养到期）、近 14 天产量与计划趋势、工单状态分布、产线负荷与产出、待办与预警、安灯呼叫。

**怎么用**：

1. 每天上班第一眼看 **待办与预警**，逾期工单、临期工单、未处置不良、设备异常都在这里。
2. KPI 异常（如 OEE 低于目标的 85%）时点进去看 **报表分析** 的 OEE 三率，判断是停机多还是节拍慢。
3. 右侧栏给出当前最需要处理的三件事。

### 3.2 生产看板（board）

**看什么**：按产线排列的卡片（设备运行数、在制工单、当前工序、产出/计划、进度条）＋安灯表。

**怎么用**：

- 适合挂在车间大屏，**每 30 秒自动刷新**。
- 现场发现问题点 **发起呼叫**：选产线、填工位、选类型（设备/质量/物料/人员）与级别（一般/紧急），提交后安灯表立刻出现。
- 问题解决后点 **关闭**，状态变「已关闭」并记录关闭时间。

### 3.3 排产计划（schedule）

**看什么**：未来两周 × 产线甘特（色块为工单，颜色代表状态）、产能负荷柱状图、待下达工单列表。

**怎么用**：

1. 先看 **产能负荷**：某产线负荷超过 100% 就要调产线或改期。
2. 在待下达列表点工单号进入详情，补齐缺口后下达。
3. 点 **新建工单** 直接建单（见 3.4）。

### 3.4 生产工单（orders）

**列表**：按状态 chips 过滤、按单号/物料/客户搜索、勾选"只看逾期"。行内显示报工/合格、进度条、工序完成数、产线、计划完成、状态、优先级。

**新建工单**：

1. 点 **新建工单**，选择产出物料（成品/半成品）、计划数量、产线、优先级、计划开始、客户。
2. 提交后状态为 **草稿**，系统按物料绑定的已发布工艺路线自动展开工序、按 BOM 展开用料。
3. 草稿状态下 **齐套率显示为「—」**，因为还没做齐套计算——这是设计而非缺陷。

**工单详情（点任意行）**：

| 区块 | 内容 | 你能做什么 |
| --- | --- | --- |
| 头部 | 数量、报工/合格、进度、标准工时、客户、产线、工艺、BOM、计划期 | 阅读 |
| 闸口清单 | 每个待推进目标的可推进状态与缺失项 | 阅读（缺失项就是"下一步该补什么"） |
| 工序与报工 | 每道工序的计划/报工/合格/不良/工时/状态 | 点 **报工** 登记产出 |
| 用料与齐套 | 每项物料需求、已发、现有、缺口 | 点 **发料** 一次发齐 |
| 检验记录 | 首件 / 巡检 / 完工检 | 阅读（检验在质量页登记） |
| 产出批次 | 入库后生成的批次号 | 点 **查看追溯** 跳转 |

**推进工单**（底部按钮）：

- 计划员/厂长看到 **下达 / 开工 / 完工确认**；仓管看到 **完工入库**；有权限者看到 **发料 / 取消工单**。
- 按钮上的"（缺 N 项）"提示还差几项，点开详情看闸口清单。
- 推进成功会提示"工单已推进到「已开工」"并自动刷新。

**报工**：

1. 点某工序的 **报工**。
2. 填合格数（默认本工序待报量）、不良数、实际工时、备注。
3. 提交后提示 `报工成功 RP… · 效率 xx%`；若这是最后一道工序且数量达标，工单自动转 **已完工**。

**完工入库**：工单「已完工」且完工检合格后，点 **完工入库**，系统生成批次号、写库存台账，并提示 `已入库，批次 B… ：xx 件`。

### 3.5 物料与 BOM（materials）

- 顶部 4 项 KPI：物料数、低于安全库存、库存金额、成品数。
- 类型 chips 切换（全部/成品/半成品/原材料/辅料），搜索编码名称规格。
- 点行打开详情：物料主档、BOM 明细、工艺路线、库存批次、近期工单、产出批次。
- **新建物料**：编码可不填（自动 `MT-xxxx`），必须填名称；类型影响能否用于建单（成品/半成品可选）。

### 3.6 质量检验（quality）

**总览**：良品率、PPM、检验单数、首件合格率、完工检合格率、未处置不良；14 天良品率趋势；缺陷帕累托（前几项即"关键少数"）。

**三个标签**：

| 标签 | 内容 | 操作 |
| --- | --- | --- |
| 检验单 | 单号、工单、类型、抽样/不良、结论、检验员、时间 | 点行看详情（含 Cpk） |
| 不良记录 | 工单、不良代码、数量、工序、处置方式 | 点 **处置** 选返修/报废/让步接收/退货 |
| 过程能力 | 被测项、样本数、规格上下限、均值、Cpk、等级 | 阅读 |

**登记检验**：

1. 点 **登记检验**，选工单（在制与待检）、类型（首件/巡检/完工检/来料检）。
2. 填抽样数、不良数；非巡检类型可填一个被测值（值与上下限用于 Cpk）。
3. 提交后提示结论：`检验完成：合格` / `让步接收` / `不合格`。

**登记不良**：选工单、不良代码、数量、工序，提交后进入待处置列表；处置完成后工单才能关闭。

### 3.7 批次追溯（trace）

**怎么用**：

1. 输入或选择批次号（也可从工单详情、库存、物料详情跳转过来，自动带入）。
2. 看 **正向展开**：本批次 → 下级组件批次（树形，含数量与产出时间）。
3. 看 **反向流向**：本批次被哪些上层批次消耗。
4. 下方列出该批次对应工单的报工记录与检验记录。

**典型问题**："客户投诉 B20261020-0001 这批网关，帮我查是哪些原料做的、还发给了谁"——输入批次号，正向树看原料，反向表看流向，10 秒内可答。

### 3.8 设备台账（equipment）

**列表**：编码、名称、类型、产线、状态、OEE 与等级、下次保养、健康度。状态 chips 过滤。

**详情（点行）**：

- OEE 环形图 + 三率拆解；14 天 OEE 趋势；停机 TOP（原因与分钟占比）。
- 状态记录、点检记录、保养工单。
- 底部按钮（设备工程师/管理员）：**报修**（置故障，必须填原因）、**转保养**、**恢复运行**、**新建保养工单**。

**注意**：故障、保养、停机都必须填原因——这是 OEE 与停机 TOP 的数据来源，不允许空着过。

### 3.9 保养点检（maint）

三个标签：

| 标签 | 内容 | 操作 |
| --- | --- | --- |
| 保养计划 | 计划号、设备、类型、周期（天/小时）、上次/下次、状态（正常/临期/逾期） | 阅读 |
| 保养工单 | 单号、设备、类型（计划保养/故障维修/点检异常）、原因、状态、停机分钟、费用 | 点 **完成** 填停机与费用 |
| 点检记录 | 单号、设备、类型、结论、点检项、点检人 | 点 **设备点检** 提交 |

**完成保养**后系统自动：工单置已完成、设备置运行、回写上次/下次保养日期、复位保养计划。

**点检**：勾选油位、气压、安全门三项，**任一项异常 → 设备自动置故障**并写状态日志，同时在设备台账标红。

### 3.10 库存台账（stock）

- 4 项 KPI：库存行数、库存数量、库存金额、仓库数。
- 仓库 chips 切换，按物料/批次搜索。
- 点批次号直接跳追溯。
- 库存来源：发料扣减（由 SCM 侧维护）、完工入库新增。

### 3.11 报表分析（reports）

**六块内容**：产量与计划趋势、OEE 三率、质量帕累托、产线负荷、设备 OEE 排名与最差、停机 TOP、物料消耗 TOP。

**怎么用**：

1. 右上切换 **7 / 14 / 30 天**。
2. 产量与达成率：`月度达成率` 用"窗口内所有工单计划量"为分母，跨期工单不会被漏算或重复算。
3. OEE 三率：可用率低 → 停机多；性能率低 → 节拍慢/空转；质量率低 → 不良多。
4. 点 **导出** 下载工单 CSV（Excel 直接打开，含 BOM）。

### 3.12 集成中心（integration）

**仅管理员可写**。六个标签：

| 标签 | 用途 | 操作 |
| --- | --- | --- |
| 集成总览 | Key / Webhook / 投递 / 变更 / 映射数量，各对象记录数 | 阅读 |
| API Key | 名称、前缀、scope、状态、最后使用 | **新建**（明文只显示一次，务必立即复制）、**吊销** |
| Webhook | 名称、回调地址、事件、状态、投递数 | **新建**（返回签名密钥，只显示一次）、**测试**、**删除** |
| 投递记录 | 事件、状态、尝试次数、HTTP 码、下次重试时间 | **重投** |
| 外部 ID 映射 | 对象类型、本地单号、外部 ID、系统 | 新增 / 删除 |
| 增量同步 | 变更流（游标、对象、动作、时间） | **拉取下一批** 续拉 |

**对接三步走**：

1. 建一个 `read` scope 的 Key，让对方先用 `curl -H "X-Fc-Key: fck_..." http://host:8021/api/orders` 跑通查询。
2. 建 Webhook 订阅所需事件（如 `work_order.reported,work_order.stock_in`），把签名密钥交给对方配置验签。
3. 对方上线对账任务，用 `/api/sync/changes?since=<游标>` 每 5 分钟增量拉取。

### 3.13 基础设置（settings）

| 区块 | 内容 | 可改 |
| --- | --- | --- |

| 组织 | 车间、产线、班组、班制 | 阅读（本期不支持在线改） |

### 3.14 操作日志（logs）

## 4 角色场景演练

### 4.1 计划员（liyun）的一个上午

1. 驾驶舱看 **待办**：3 张逾期工单、2 张临期。
2. 进 **排产计划**，看到 LN-302 负荷 118%，把一张工单改到 LN-303。
3. 进 **生产工单**，筛选「草稿」，打开 WO…0005，闸口提示"物料齐套率 83%"。
4. 让仓管发料后回来点 **下达**，按钮上的"缺 1 项"消失，下达成功。
5. 点 **开工**（需首件合格、已派工、设备可用），系统提示"首件检验未合格"→ 通知质检做首件。

### 4.2 操作工（zhaolei）的报工

1. 生产看板找到自己产线的工单，或直接进工单列表按状态「已开工」筛选。
2. 打开工单，点当前工序的 **报工**，合格数默认待报量，填实际工时。
3. 提交后状态栏显示 `报工成功 RP… · 效率 96.5%`。
4. 遇到拧紧机报警，点看板 **发起呼叫**（类型设备、级别紧急），等设备工程师处理。

### 4.3 质检员（sunqi）的三检

1. 首件：**登记检验** 选工单 + 类型首件 + 抽样数 + 被测值 → 结论合格后操作工才能报工。
2. 巡检：每 2 小时登记一次，发现不良 → 登记不良（代码 + 数量 + 工序）。
3. 完工检：工单完工后做完工检，0 不良 → 合格 → 仓管可入库；≤3% → 让步接收（仍可入库）；> 3% → 不合格，需返工。
4. 在 **质量检验 → 不良记录** 处置不良（返修/报废/让步/退货）。

### 4.4 设备工程师（zhouhang）的保养

1. **保养点检** 看逾期计划，选设备 **完成保养**（填停机分钟与费用）。
2. 现场点检：提交点检，若安全门异常 → 设备自动置故障，回设备台账 **恢复运行**。
3. **设备台账** 看 OEE 排名，对最差设备查停机 TOP，定位主因。

### 4.5 仓管（wuping）的收发

1. 工单详情点 **发料**，一次发齐 BOM 全部用料，齐套率变 100%。
2. 工单完工且完工检合格后，点 **完工入库**，生成批次并写库存。
3. **库存台账** 按批次核对，点批次号可查追溯。

### 4.6 厂长（qianwei）的日报

1. 驾驶舱看 6 项 KPI 与 14 天趋势。
2. **报表分析** 切 30 天，看产量达成率、OEE 三率、缺陷帕累托、设备排名。
3. 点 **导出** 拿工单 CSV，附在日报里。

## 5 离线 DEMO 使用

`demo/feichi-mes-demo.html` 是**单文件演示版**：

- **双击打开**即可（`file://`），无需服务、无需网络、无需登录。
- 内置确定性数据快照，14 个页面全部可用，图表、看板、追溯都能看。
- **写操作在浏览器内存生效**：可以真的新建工单、报工、关安灯、登记检验、改设备状态、完成保养、生成 API Key；页面重载后状态由 `sessionStorage` 保住，关掉标签页即恢复初始。
- 适合客户演示、新人培训、出差汇报。**不要用于生产数据**。

## 6 常见问题（FAQ）

**Q1：为什么点「下达」没反应/提示缺项？**
闸口要求：数量 > 0、工艺路线已发布、BOM 有明细、齐套率 100%。缺料就先去 **发料** 或补库存；没工艺就先去补工艺并发布。

**Q2：为什么报工提示"首件检验未合格"？**
规则 `fai_required = 1`（默认开启）。到 **质量检验 → 登记检验** 给该工单做一次首件检验，结论合格即可。若确需跳过，管理员在 **基础设置** 关闭该规则。

**Q3：为什么「完工入库」按钮是灰的？**
需要状态「已完工」＋完工检合格。先确认所有工序都报完且报工量 ≥ 计划量，再做完工检。

**Q4：齐套率显示「—」是什么意思？**
草稿状态的工单还没做齐套计算，显示「—」；下达前系统会实算，不足会拦截。

**Q5：产量和入库量对不上？**
报表产量采用**末工序法**（每张工单只计末道工序报工）。若差异明显，检查是否有工单的末工序报工量与实际入库量不一致，或是否跨期间。

**Q6：OEE 特别低/特别高怎么排查？**
点设备详情看三率：可用率低看停机 TOP；性能率低看节拍与空转；质量率低看不良。

**Q7：追溯查不到批次？**
确认批次号完整（`B` + 日期 + 流水），或从工单详情的「产出批次」直接点进去。批次由完工入库生成，未入库的工单没有批次。

**Q8：Webhook 一直失败？**
先看 **投递记录** 的 HTTP 码与错误信息；确认回调地址从公网可达、验签算法为 `HMAC-SHA256(secret, timestamp + "." + rawBody)`、时间戳偏差 ≤ 5 分钟。失败会按 30×2^n 秒退避 3 次，之后可手动 **重投**。

**Q9：忘了 API Key 明文怎么办？**
无法找回（只存哈希）。吊销旧的、新建一个即可。

**Q10：能改端口/换数据库吗？**
能。`FEICHI_PORT` 改端口，`FEICHI_DB` 指定库文件。换库后首次启动会自动建表并写演示数据。

## 7 运维指南

### 7.1 启动与守护

```bash
# 前台启动（调试）
python backend/server.py

# Linux systemd（示例）
[Unit]
Description=Feichi MES
After=network.target
[Service]
WorkingDirectory=/opt/feichi-mes
Environment=FEICHI_PORT=8021
ExecStart=/usr/bin/python3 backend/server.py
Restart=always
[Install]
WantedBy=multi-user.target
```

Windows 可用「任务计划程序」开机启动，或写一个 `start.bat` 放到启动目录：

```bat
@echo off
cd /d D:\feichi-mes
python backend\server.py
```

生产建议前置 Nginx 做 HTTPS 与静态缓存，并限制 `/api/integration/*` 只对管理网开放。

### 7.2 备份与恢复

```bash
# 冷备：停服务后复制单文件
cp backend/data/feichi.db /backup/feichi-$(date +%F).db

# 热备（服务运行中）
python -c "import sqlite3;c=sqlite3.connect('backend/data/feichi.db');c.execute(\"VACUUM INTO '/backup/feichi-hot.db'\")"
```

恢复：停服务 → 用备份文件覆盖 `backend/data/feichi.db` → 启动服务。

### 7.3 重置演示数据

停止服务，删除 `backend/data/feichi.db`（含 `-wal`、`-shm`），重新启动即重建。

### 7.4 健康检查与监控

```bash
curl http://127.0.0.1:8021/api/health
# {"data":{"ok":true,"workOrders":37,"equipment":25,"journal":"wal"}}
```

建议监控：HTTP 200 率、`/api/health` 响应时间、数据库文件大小、磁盘剩余空间。

### 7.5 常见故障

| 现象 | 排查 |
| --- | --- |
| 启动报端口占用 | `netstat -ano | findstr 8021`，改 `FEICHI_PORT` 或结束占用进程 |
| 页面打开空白 | 打开浏览器控制台看报错；确认 `frontend/` 完整、JS 未被截断 |
| 登录后立即被踢回登录页 | 令牌失效或 Cookie 被清；重新登录；检查浏览器是否禁用本地存储 |
| 写入报 `database is locked` | 并发过高，已被写锁串行化；若持续出现，检查是否有长事务或外部进程占用库文件 |
| 报表数字与现场不符 | 核对是否跨期间、是否有工单漏报工、是否有工序超报 |
